## Plan

One service, one client module per side, one registry:

- **Model home** `~/Forge/models/` (gitignored, created 2026-10-08; env `FORGE_MODELS_DIR`). Voice uses `models/voice/stt/<id>/` and `models/voice/tts/<id>/`. Existing files are hardlinked in (no extra disk) or referenced by a `reuse` path.
- **Registry** `shared/voice_registry.json`: every STT and TTS model (id, kind, tier fast/best/default, engine, files, size, voices, download URLs + sha256, reuse paths). The research picks fill it.
- **Voice app** `apps/voice` (port 8467, `start_at_launch`, section system): the only process that loads speech models. Workers per model in child processes (nice 10, CPUs 4-11, 4 threads), loaded on first use, unloaded after idle. Mic capture with `pw-record`, smart push-to-talk (hold = talk while held; tap = talk until silence or next tap), earcons, one updating desktop notification, server-side playback for replies. Page: models, per-app picks, mic and speaker tests, downloads, history, hotkey.
- **Shared Python client** `shared/forge_voice.py` (stdlib): speak/say/transcribe, speech_text (markdown to speakable), clean_heard (fillers, wake words, number words), split_target, ensure_running. **Shared JS** `shared/forge_voice.js`: mic button, speak, speak-replies toggle, state events.
- **Commands**: one registry stays Acchan's tool registry. Tools gain optional `phrases=[...]` (natural examples with `{slot}`s) declared on the `@tool` itself; a fuzzy matcher (`acchan/phrases.py`) maps utterances to tool calls after the fast path and before the model. Relay's commands become Acchan tools (`acchan/tools/relay.py`, calling the same `relay` CLI) so voice, Jan and MCP all reach them. New `POST /api/voice/command` on Acchan runs fast path, then phrases, then (optionally) the Jan agent, and returns one JSON answer.
- **Routing anywhere** (hotkey): heard text, cleaned; "stop/quiet/say that again/cancel" handled by the voice app; leading "Claude/Tetsu" sends it to Claude through the Relay chat (the same `relay` CLI call Mission's relay chat uses, as if typed on WhatsApp) and speaks the reply when it lands; leading "Jan/Acchan" or nothing goes to Acchan's `/api/voice/command` (commands first, then Jan). Default target is a setting.
- **Apps**: Claude app mic (dictation into the composer) + speak-replies toggle for normal chats; Acchan's voice moves to the shared service (endpoints kept); Mission Control gets the mic and speak toggle in its new chat view, coordinated with relay-109-work; the Forge hub needs no forge.py change (hotkey goes straight to the voice app).
- **Hotkey**: Super+Z by default (free in GNOME and Hyprland; checked before writing). GNOME custom keybinding (press = tap). Hyprland `custom/keybinds.lua` pair: press `forge-voice down`, release `forge-voice up`. Installer is idempotent and backs up first. The CLI starts the voice service itself if Forge was started before the Voice app existed (no Forge restart needed today).
- **Resources**: CPU by default; iGPU only as an opt-in for engines with OpenVINO, never while `llama-server` holds a model; the near-human TTS is load-on-demand with a RAM check and is never the default.

## Contract (what the helpers build against)

### Voice service, http://127.0.0.1:8467 (`apps/voice`)

- Guard: every route except `GET /api/status`, `GET /` and static files needs header `X-Forge-Voice: 1`. CORS allows only `http://127.0.0.1:*` and `http://localhost:*` (with that header), so a web page elsewhere cannot start the mic or read transcripts.
- `GET /api/status` -> `{state: idle|listening|transcribing|thinking|speaking, loaded: [{id, kind, idle_s}], mic: {ok, tool}, version: 1}` (no text in it).
- `GET /api/registry` -> `{models: [{id, kind, label, tier, engine, size_mb, present, voices}], defaults, disk_free_gb}`.
- `GET|POST /api/settings` (POST merges a partial object, validated) -> settings.
- `GET /api/apps` -> rows for "anywhere" plus every app whose `forge_app.json` has a `voice` field, each with resolved stt/tts/voice/speed/speak_replies.
- `POST /api/stt?app=<name>` body = audio bytes (wav/webm/ogg/m4a; ffmpeg converts to 16 kHz mono) -> `{text, model, ms}`; 400 for empty or over 120 s / 20 MB, 503 with a plain message on engine failure.
- `POST /api/tts` `{text, app?, model?, voice?, speed?}` -> `audio/wav` (headers `X-Voice-Model`, `X-Voice-Seconds`). Text goes through `forge_voice.speech_text` first. 400 nothing to say, 503 on failure.
- `POST /api/say` `{text, app?, ...}` -> plays on the laptop speakers (queued, `pw-play`), answers at once `{ok, queued}`. `POST /api/hush` stops speech and clears the queue.
- `POST /api/ptt/{down|up|tap|cancel}?target=auto|jan|claude|text` -> `{state}`. Hold longer than `ptt.hold_s` then up = stop and process; a short press = keep listening until silence (`ptt.silence_s`), another tap, or `ptt.max_s`. `cancel` discards.
- `GET /api/events` (SSE) -> `{type: state|heard|result|error|level, ...}` (level at most 10 a second while listening).
- `GET /api/history` -> last 50 `{at, heard, target, handled_by, reply, ms}`.
- `POST /api/models/{id}/download`, `GET /api/models/{id}/download` (progress), `DELETE /api/models/{id}` (only files inside the model home, never `reuse` paths; 409 while loaded). `POST /api/unload` frees every model now.

### Settings `~/.config/forge/voice.json` (written only by the voice app)

```json
{"stt": {"model": "<id>"},
 "tts": {"model": "<id>", "voice": "<voice>", "speed": 1.0},
 "apps": {"claude": {"tts": {"model": "<id>", "voice": "<v>", "speed": 1.0}, "stt": {"model": "<id>"}, "speak_replies": false}},
 "anywhere": {"target": "auto", "speak_replies": true, "earcons": true, "notify": true},
 "ptt": {"hold_s": 0.35, "silence_s": 1.2, "max_s": 30},
 "resources": {"threads": 4, "cpus": "4-11", "idle_unload_s": 300, "device": "cpu"},
 "max_chars": 1500}
```

App value, then the global value, then the registry default.

### Acchan `POST http://127.0.0.1:8451/api/voice/command`

Request `{text, use_model: true, source: "voice"}` -> `{handled_by: fast|phrase|jan|none, reply, calls: [{tool, args, ok}], ms}` (plain JSON, not SSE; 90 s cap). With `use_model: false` and no match: `handled_by: "none"`, empty reply.

### Manifests

`forge_app.json` may carry `"voice": {"listens": true, "speaks": true}`; the voice app lists exactly those apps (discovered, no list in code). Documented in `README.md`.
