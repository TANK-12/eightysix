## A22 (a): pop an app out onto another screen
Right-click any app (tile, dock or sidebar) > **Pop out** ("own window,
another screen"). forge.py opens the app's own address in a second window
(new `forge_popout.py`): with 2+ monitors it fills a monitor Forge is not on
(the pointer's first, else the next one along); with one monitor it opens as
a normal window. F11 toggles its full screen, Esc leaves it, "Back into
Forge" in its title bar closes it and brings the app to the front in the
hub. The hub goes home when the app it is showing is popped out, so the app
is never on screen twice. An app the hub never opened is started first and
the window waits up to 30 s for it. App size zoom follows Settings; Quit
closes the pop-outs.

Files: `forge_popout.py` (new), `forge.py` (pop_out + message `popout`,
zoom, quit), `hub/index.html` (popOut, forgePoppedBack, menu item),
`tests/test_popout.py` (new), `tests/browser/hub_polish_harness.js` (+1).

## B40: background mode's entrance and the Alt+V pulse
- **Alt+B** now opens with a bloom of light over the picture (1.4 s, on
  `#pulse-light`, so the wallpaper's own drift animation is untouched).
  Setting: Background mode > Entrance animation.
- **Alt+V** (new Forge key `pulse`, "Background pulse") starts background
  mode with the pulse: the whole wallpaper swells and brightens on each beat,
  the edges glow in the accent colours (second accent on strong beats), a
  soft light blooms from the middle, and the picture sways a little, more on
  the beat. Alt+V again stops it; Esc/Alt+B leave both. Settings (Background
  mode group): Pulse strength, Edge glow, Sway.
- How: `Pulse` in hub/index.html reads the visualiser's levels
  (`Visual.frame` calls `Pulse.feed(v)`), so it listens to whatever Settings
  > Visualiser listens to (system audio through cava, or the background
  music). With the visualiser off, Visual runs a "quiet" style that draws
  nothing. A beat is the lows jumping 30% above their running average.
- The settings entries in shared/forge_theme.py went into git inside Kiko's
  commit 407e420 (swept up with visualiser_in_apps); the hub side is in
  this session's B40 commit, which also carries Kiko's three hub lines for
  visualiser_in_apps (#279).

## App folders by drag (Emerson: "just let me drag apps and stuff")
- Drag an app tile (or dock icon, or bar button) onto another app: the two
  become one folder tile, named after the first app's section, with the
  members' icons in a 2x2 grid; Undo in the toast. Drop an app on a folder
  to add it. Open the folder: a chooser of its apps with an editable name.
  Right-click: an app in a folder has "Take out of folder"; a folder has
  "Rename folder" and "Ungroup". A folder left with one app dissolves.
  Apps in a groups/*.json group (declared, e.g. pixel games) are not
  draggable.
- How: setting `app_folders` ({id: {label, members}}, custom, no Settings
  row) in shared/forge_theme.py (`_clean_folders`: 2+ members, one folder
  per app); forge.py's save_hub_settings accepts it. The hub turns each
  folder into a group (`folderGroup`, id `f-<id>`), so tiles, chooser, bar
  strip and dock reuse the groups code; `Folders` in hub/index.html does
  the drag, save, Undo and the live rebuild (open apps stay open).
- Verified: tests/test_app_folders.py 4 pass; new hub_folders harness 23
  PASS (real DragEvent drops); full run.sh 590 PASS 0 FAIL; all tests/ +
  settings tests 253 pass; pyright 0 errors on forge_theme.py; screenshots
  of the folder tile and its chooser looked at.
