### H2. Above x1.5 the power knob stops raising peak torque, so continuous torque can exceed peak (CONFIRMED)
- knobs.json derives `torque_limit_nm = torque_peak_nm x 1.5` before the knobs apply (registry.py:94-97), and the power knob does not scale it. parts.py:169-179 then caps peak at that limit, and part-level power (parts.py:168-170) hits the same cap.
- POST /api/model exo_full with knobs.actuators.harmonic_m.power = 1 / 1.5 / 2 / 20 gives J1 (cont, peak) = (30,60) / (45,90) / (60,90) / (600,90). knobs.parts["exo_full/J1"].power=20 gives (600, 90). check() (benches/__init__.py:115) then fails a joint because "peak is 90" while its continuous rating is 600. This contradicts knobs.json: "Power on a joint is a bigger motor all round".

### H3. Hand sag is never judged, and a zero-size strut reads "held cleanly" (CONFIRMED)
- No rule compares hand_sag_mm with a limit; it is only displayed (benches/__init__.py:326, hold.py:92/105). In `_beam` (arm.py:356-365), d_mm=0 makes c=0, so stress is 0 and safety is 999.0.
- Override `models.exo_full["links.2.section.d_mm"]=0` (upper_arm_link), shoulder_hold: safety 999.0, 0.0 MPa, 0.0 kg, tip 43399044283.8 mm. The first card says "held cleanly, hand sags 43399044290.0 mm, weakest beam safety 9.4", and the verdict is unchanged. Because only sag reads link stiffness, the **stiffness** knob on materials and links can never change a verdict.

## MED
### M1. Nothing bounds how long a run takes (CONFIRMED scaling, extrapolated)
- shoulder_rom on exo_lite takes 628 ms at plane_step 10 and 3039 ms at 2: linear in 1/step. So plane_step 0.01 would take about 10 min and 0.001 about 100 min. fps 1e5 on lift/motions would behave the same way. /api/run is a sync route with no timeout, so a run pins a worker thread while the page spins. The field is visible without advanced mode. I did not run these to completion.
### M2. A missing profile name is silently the baseline, never a 404 (CONFIRMED)
- registry.py:240-241 returns an empty profile when the file is absent; GET (web_app.py:383) and copy (:398) both rely on it.
- GET /api/derive/exo_full?profile=typo_name returns 200 labelled "typo_name" with baseline numbers (jump 0.38). Copying typo_name to made_from_nothing returns 200 and creates an empty profile. The game URL `profile=<name>` therefore plays baseline stats under a typo'd name.
### M3. An `only` value that names no motion passes with nothing tested (CONFIRMED)
- motions.py:27 filters without checking for a match; web_app.py:326-327 passes any string. POST /api/run {"model":"exo_full","test":"shoulder_motions","only":"nope"} -> 200 verdict pass, 0 motions, 0 cards.
### M4. The worst-misalignment card never shows fail (CONFIRMED)
- shoulder_rom.py:100 chooses only warn or pass, but the per-cell rule fails above 30 mm. exo_lite with `shoulder.mechanism` = lateral_gimbal or tilted_gimbal: card "warn 47 mm", 208 misalign cells, verdict fail. Same on exo_full.
### M5. Swapping exo_lite to the soft cable fits a QDD motor as the cable drive (CONFIRMED)
- parts.py:218-222 applies the model's girdle-specific `mechanism_overrides` to whatever mechanism is swapped in. exo_lite plus soft_cable gives J1 = qdd_planetary; exo_full gives cable_bowden. Mass, top speed (25 vs 6 rad/s) and energy then come from the wrong drive. The about text and the WIP invite this swap.
### M6. Non-finite pose input is accepted and can pass (CONFIRMED)
- PoseIn (web_app.py:291-298) accepts NaN/Infinity, and web_app.py:312 `max(0.0, payload)` lets +inf through. Non-finite numbers fail no comparison and FastAPI serialises them as null.
- Raw body {"model":"exo_full","payload_kg":Infinity} -> 200, level **pass**, torques null, every beam at safety 999.0. "plane":NaN -> 200. "elev":Infinity -> 400 with numpy's "expected a finite input". With every arm joint set to free_bearing, lift_cycle returns `lifts_per_charge: null` and a card reading "inf", level pass (lift.py:45,76).
### M7. A non-object `knobs` gives a 500 (CONFIRMED)
- registry.py:260 calls `.items()` without a type guard; overrides do have one (registry.py:118). Inline {"knobs":[1]}, "x" or 5 on /api/run -> 500, and PUT /api/profiles/crit1 {"knobs":"x"} -> 500.
### M8. Some editor knobs never reach any bench (CONFIRMED by grep and by H3)
- Shell **strength** and the hip/knee drives are read only in derive.py:72 and :145 (game stats); no bench uses them. Link and material stiffness only move the unjudged sag (H3). In the tester these knobs change the parts table and nothing else, which falls short of the request's "sees the effect in the test".
