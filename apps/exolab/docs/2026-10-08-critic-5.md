### C5-M1. dropStaleKnobs misses the other suit's knob after a swap of the shared mechanism (Medium)

  root cause: both shipped suits use girdle_tracking, and the Parts tab's J1..J3 "Drive" row
  (editor.js:997, `fieldRow("mechanisms", mechId, "joints.N.actuator")`, no Advanced guard) writes
  `overrides.mechanisms.girdle_tracking`, which Registry.model_mechanism applies to every model on
  that mechanism (after the model's own mechanism_overrides).
- UI path: exo_full Parts, J1 power x2; open exo_lite; swap its J1 Drive to the free bearing; Save.
- Probe (p1.py, section D): profile `knobs.parts["exo_full/J1"].power = 2` +
  `overrides.mechanisms.girdle_tracking["joints.0.actuator"] = "free_bearing"`.
  POST /api/model exo_lite -> 200, part_knobs J1 = ['weight'], warnings =
  ['parts/exo_full/J1: no motor, so no power knob (...)']; PUT -> 400 "parts/exo_full/J1: no motor,
  so no power knob (a passive drive has nothing to make bigger)". Reverse (knob on exo_lite/J1, swap
  made on exo_full): same 400 naming exo_lite/J1.
- Probe (p3.mjs, the real `prune` + `dropStaleKnobs` source cut out of editor.js, real store.js,
  node): S.modelId exo_lite, S.model = that /api/model answer, S.modelFor = profileKey():
  knobs after = {"parts":{"exo_full/J1":{"power":2}}}, toasts = [] (nothing dropped). Control with
  exo_full open: knobs after = {}, toast "Dropped knobs nothing reads now: J1 power."
- Effect: exactly the C4-L5 trap ("Not saved: parts/exo_full/J1 ..."), with the knob on a suit
  that is not even open; the README's "the editor drops one its part no longer reads ... so Save
  still works" does not hold here.
- Fix: check every model's part knobs, not only the open one (e.g. /api/model returns
  part_knobs for each model a part knob names, or a small GET /api/part-knobs?profile=...).
- Note: opening the suit the error names clears it (its own /api/model answer then drops the
  knob, p3 control case), so there is a way out, but nothing on screen points to it.
