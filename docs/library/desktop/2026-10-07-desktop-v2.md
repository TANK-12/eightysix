## What is new (all in place, nothing removed)

Files: `shared/forge_particles.js`, `shared/forge_visual.js`,
`shared/forge_widgets.js`, `shared/forge_widgets.css`, `shared/forge_depth.js`,
`shared/forge_theme.py` (labels, keys), tests `tests/test_desktop_v2.py` +
`tests/desktop_v2_node.js`, `tests/test_hub_widgets.py`,
`tests/browser/hub_fx_harness.js`, bench `tools/desktop_bench.py` + `.html`.
Pre-edit copies: `backups/2026-10-07-overhaul/desktop/`.

**Particles**
- Motion is per second, not per frame: at a 30, 20 or 5 fps cap they move as
  fast as at 60 (board note #931: they crawled). A gap over 250 ms counts as a
  rest, so coming back from hidden never jumps.
- Depth: most kinds are born at a depth; near ones are bigger, quicker,
  brighter and slide further with the pointer (parallax).
- New kinds: **Spirit wisps** (lights on a slow current with comet tails) and
  **Galaxy** (a turning two-armed spiral round a bright core). Labels and
  wallpaper-name words in `forge_theme.py`.
- Cheaper drawing: rain, bubbles, glitter and constellation lines batched into
  at most 6 paths by opacity step (constellation: 6 strokes a frame instead of
  one per pair); petals and lanterns are pre-drawn sprites; no
  save()/restore() per particle; squared distances.
- Stops completely while hidden, while `forge-visible`/ForgeIdle says it
  cannot be seen, on the paused power tier, and when there is nothing to draw
  (amount 0). Fixed: the `rays` kind called a `hexAlpha` that only the hub
  defined (would throw on the desktop page).

**Visualiser** (`forge_visual.js`)
- Bars: one gradient and one path for all 64 bars (was 64 gradients + 64
  fills), peak caps that hold then fall; narrow cards no longer throw.
- Ring: a bass glow behind it, spokes in ≤12 strokes (was 96).
- Mirror batched (≤12 fills, was 96); Orbit stamps a cached glow sprite (was
  ~110 radial gradients a frame).
- New styles **Spectrum** (smooth mirrored spectrum, tapered ends, fading
  reflection) and **Nebula** (clouds of light per band; fills a card).
- An unknown style name draws bars instead of nothing.

**Widgets** (registry: each one `W.define`)
- New: **Activity** (CPU, memory, GPU over 1/2/5 min; CPU heat when the stats
  carry `temps`), **Battery**, **Countdown** (date + optional time; set for
  MATH1014 in the screenshots), **World clocks**, **Focus timer** (work/break
  ring, rings even off-screen), **To do**, **Moon** (phase drawn once a day).
- Clock: analogue face option (hands turned by transform once a second).
- New option kind `date`. The visualiser card's style menu is ForgeVisual's
  own list, so a new style appears with no edit.
- Visualiser card: draws only while seen, at its own cap (20/30/60, default
  30; 20 on the reduced tier), 4 fps in silence for still styles, no rAF at all
  while hidden or paused.
- Looks: soft top light on cards, hover lift, page-turn entrance
  (transform/opacity only), gradient meters, dashed memory line.
- Glass cards: blur 12 px (was 18); on the reduced tier no backdrop blur, a
  thicker flat fill.
- Bad stats (null, text, NaN, wrong types) show "–" instead of `NaN%`,
  `undefined GB` or a frozen card.

**3D wallpaper** (`forge_depth.js`)
- Zoom bug fixed: the strength shown is eased; behind an open app
  (`body.in-app`, watched by the file itself) it eases to 0, so the picture
  goes back to a plain cover fit (no extra zoom), then the loop stops.
  Screenshot pair: old home/app vs new home/app, `/tmp/dv2/depth/grid.png`
  (scratch).
- GPU cost: canvas drawn at 3/4 of the screen (1/2 reduced, never above
  1920 wide; was full size up to 2560), ray walk 10 steps while only drifting
  (16 when the pointer moves, 8 reduced; was always 16), drift 20 fps (was 24;
  12 reduced). Paused tier draws nothing.

**Power tier**: everything reads `power_tier` from the eased theme the host
hands it (`ForgePower.apply()`, helper-3's `forge_power.js`), text such as
"reduced: GPU busy" included. full = as set; reduced = the eased amounts/rates
plus a 30 fps ceiling (widget visualiser 20, depth 1/2 res, 8 steps); paused =
nothing drawn.

**Keys** (`forge_theme.py` HUB_KEYS, shown and rebindable in Settings):
`Alt+W` widgets page (again = back), `Alt+Q` close the open app.

Also measured: motion per second at 60 vs 20 fps differs by under 4%, at 5 fps
under 20% (the first frame after start counts as one ordinary frame); before
v2 a 20 fps cap moved them at a third of the speed (reasoned from the per-frame
code, not measured).

Not measured: GPU busy % (the bench has `--gpu` and reads per-process GPU time
from DRM fdinfo, the numbers intel_gpu_top shows per client, but it was not
run before the stop-measuring call). Depth savings are reasoned: 0.5625x the
pixels, ~0.6x the texture reads per pixel while drifting, 20/24 the frames.

## Two-finger page swipe on the desktop (added 2026-10-07, 21:20)

Emerson: "make the widget page swipeable by 2 finger just like in forge cause
3 fingers is desktop swiping".
- `desktop/forge_desktop.js` `clickable()`: with two or more pages the whole
  `#widgets` area joins the input region, so a swipe over bare desktop
  reaches the page (before, only the cards took input, so swipes fell
  through). One page: unchanged, clicks pass through as before. Desktop
  icons (ding) are off, so nothing on the bare desktop is covered.
- `shared/forge_widgets.js` wheel handler (hub and desktop both): touchpad
  steps add up over one swipe (60 px), one swipe = one page including its
  glide, line/page wheel modes scaled. Before, one step had to be 30 px.
- **Verified**: `tests/browser/desktop_widgets_harness.js` 42/42 pass (new: area
  takes input with 2 pages, slow swipe turns, glide doesn't double-turn, back
  swipe, vertical scroll ignored, 1 page = pass-through). hub_widgets/hub_fx
  pass. hub_level and hub_music_skip fail with the off-screen WebKit GL core
  dump (environment, not this change).
- **Not verified**: a real touchpad swipe on the live desktop; needs the
  desktop script restarted (GNOME re-login) to load. Backups:
  `backups/2026-10-07-desktop-swipe/`.
