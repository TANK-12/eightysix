# Eighty Six: the guide (run, play, build, test, find things)

date: 2026-10-07 · for: both (Emerson, and any Claude session with no history) · written by Ami (Relay 65)

Companion docs, same folder: `2026-10-07-handoff.md` (what state every system is in, honestly rated) and
`2026-10-07-roadmap-to-beta.md` (what to build next, in order, from 0.1 to beta).

## What the game is

Eighty Six is a from-scratch game about the Juggernaut walkers from the anime *86*. You drive a four-legged,
5.4-tonne Juggernaut over real terrain and fight the Legion (three machine types) with a 57 mm gun, two 12.7 mm
sub-arm guns, a wire anchor and a blade strike. Every move comes from physics: legs, motors, recoil and the wire
push the mech, nothing is animated or faked. It is built in **Godot 4.7.2** (a free game engine) with **Jolt**
(its physics engine), lives in `~/Games/eightysix` (its own git repo, no remote) and is at **0.1.0-alpha**,
saved version **018** (2026-10-07). About 29,000 lines of game code and tools, 11,000 lines of tests.

## Play it

- **Forge hub:** the Eighty Six tile (section Play), button **Play**. The tile also shows test results, frame rates
  per graphics preset, the check-image galleries and the saved versions, each with its own Play button.
- **Desktop:** the "Eighty Six" launcher (right-click it for the previous version).
- **Terminal:** `~/Games/eightysix/tools/play.sh`. It rebuilds the game first if any source changed (a few
  seconds), then runs it. `tools/play.sh --version 17` plays a saved version; `python3 tools/builds.py list`
  shows each version's note.
- **How to play, every control, what to try:** `~/Games/eightysix/PLAYTEST.md`. The short version: WASD + mouse
  or a PS5 pad, Shift run, Space jump (hold to charge), Ctrl slide, left mouse 57 mm, right mouse sub-guns,
  F wire anchor, V cockpit view, Tab Handler (squad) view, O photo mode, Esc pause. All rebindable in
  Settings > Controls; Settings has a search box (Ctrl+F).
- **What there is to play:** main menu > Deploy starts **First contact** on Ashen valley (three waves). Select
  map has the rest: Sector 86 frontier (4 km, mission **Frontier sweep** with the bridge drop), Palouse grassland,
  Allegheny forest and Brilon (real places, free roam only), the Test range and two Test bench grounds.
- **Your notes:** write them in `~/Games/eightysix/NOTES.md`, any form, or tell a session "Eighty Six notes: ...".

## Open it in the editor

`godot -e --path ~/Games/eightysix` (or the hub tile's "Open in Godot editor"). The game starts from
`scenes/boot.tscn`. Settings are saved to Godot's `user://settings.cfg`; tests and bot runs never write them.

## Test it

- **One area:** `tools/run_tests.sh test_hangar` (the argument is a name filter, one per run; it matches by
  substring, so `test_look` also runs `test_look3`). Headless (no window), a few seconds per file.
- **Everything:** `tools/run_tests.sh` with no argument. About **10 minutes**; last full run 2026-10-07 21:31:
  **522 passed, 1 failed** (the failure is the unfinished stand-up work, see the handoff). Results also go to
  `logs/tests-last.json`, which the hub tile reads.
- **Python tools:** `python3 -m unittest discover -s tools/tests` and `-s tools/audio`.
- Tests are Godot scripts in `tests/test_*.gd`, run by `tests/runner.tscn`: 63 files, one per system.
  Physics runs at a fixed 120 ticks a second, exactly like the game.

## Watch it play itself (bot runs)

A **bot run** plays a scripted sequence in the real game on the real graphics card, off screen, and saves
screenshots and measurements:

- `tools/bot_run.sh <name> [--preset=low|medium|high|ultra] [--visible]` plays `tools/bot/<name>.json` and
  writes `images/NNN-<name>/` (next free number; shots, `report.json`, logs). 116 scripts exist; useful ones:
  `smoke` (menus, settings, a walk), `a011_views` (fixed views of every map + Hangar close-ups, with fps),
  `jg_check` (walk and run), `combat_check`, `a4_mission`, `b5_mission`, `long_walk` (10-minute soak),
  `score_move` (the movement scoreboard: top speed, slide, scrapes).
- **One GPU job at a time on this laptop.** Before a bot run, post a line on the crew board `forge`
  (`python3 ~/.claude/skills/crew/crew.py post forge <you> "..."`) and read it first
  (`python3 ~/.claude/skills/crew/crew.py notes forge`) to see whether someone else is running one.
- **Frame rates:** `tools/fps_log.py` writes `logs/fps/*.json` (the hub's Frame rates panel reads them). Read fps
  only on a quiet machine; other sessions' runs spoil the numbers.
- Contact sheets and image checks: `tools/contact_sheet.py`, `tools/histogram.py` (brightness), `tools/sharpness.py`.

## Build and share it

- `tools/play.sh` keeps `build/linux/` current by itself (`tools/builds.py ensure`).
- **Save a version** (a numbered copy that is never deleted): commit everything first, then
  `python3 tools/builds.py save --note "what is new, and where to see it"`. It refuses while git shows
  uncommitted changes. Versions live in `build/versions/NNN-YYYY-MM-DD_HHMM/`.
- **Other platforms:** `tools/export.sh linux|windows|macos` (templates for all three are installed;
  platforms are one entry each in `tools/platforms.json`).
- **Share zips for friends:** `python3 tools/builds.py share` (or the hub's "Make share zips") makes Windows,
  Linux and macOS zips of the newest version in `build/share/`, each with an install script and HOW-TO-RUN.txt.
  The 86 soundtrack is personal-use only and is left out of them (the game plays the player's own music folder
  instead).
- `build/`, `images/` and `logs/` are git-ignored and can grow large (build is 1.7 GB today). Never delete
  versions or image folders; move to the trash with `gio trash` if space is needed, and ask first.

**The data registries** (`data/*.json`, loaded by `scripts/core/registry.gd`). Adding a map, mech, weapon,
weather, sound or setting is one entry in the right file, never code. An entry can `"inherits"` another and
override a few fields. The main ones:

| file | holds |
|---|---|
| `maps.json` | the 8 maps: terrain, roads, towns, scatter counts, palette, weather, mission |
| `mechs.json`, `parts.json` | the mechs and their 98 parts (mass, health, armour in mm, joints, motors) |
| `weapons.json` | 9 weapons, real calibres, muzzle speeds, penetration |
| `enemies.json` | the three Legion types (Ameise, Grauwolf, Löwe): AI numbers, sounds, fall damage |
| `missions.json`, `squad.json`, `radio.json` | the two missions, the wingmen, the Handler's lines |
| `weather.json`, `graphics_presets.json` | 8 lighting and sky set-ups; the four presets Low to Ultra |
| `kit.json`, `town_styles.json` | the asset kit (rocks, walls, ruins, props, grass) and how towns are built |
| `tuning.json` | physics and feel numbers that are not per-entry (righting, slide, dust, destruction) |
| `settings.json`, `input.json` | every setting with its page, default and help line; the 65 key bindings |
| `hangar.json`, `finishes.json`, `emblems.json`, `themes.json` | showroom lights, paint jobs, decals, UI themes |
| `sounds.json`, `music.json` | every sound effect and music track |

## Glossary (plain words for the terms these docs use)

- **AP / HE / APFSDS:** shell types. AP is armour-piercing (a hard slug that punches through plate); APFSDS is the
  modern dart version (a thin tungsten dart; "the dart" in the game); HE is high explosive (bursts, pushes and
  breaks things, weak against thick armour).
- **Collider / hitbox / convex hull:** the invisible simple shape the physics engine uses for a part; a convex
  hull is the tightest shape with no dents that wraps the visible part.
- **Triplanar:** a way to put a texture on a model that has no texture layout, by projecting it from three sides.
- **Tone mapping, white point:** how the game turns its very bright internal light values into screen colours; the
  white point is how bright something must be to show as pure white (left unset, it made everything washed out).
- **Frame pacing floor:** Ultra never shows more than 15 frames a second in our runs, however light the scene;
  something holds frames back, cause not found.
- **A\* (A-star), nav grid:** the standard way to find a path across a map; the grid is the map cut into 16 m
  squares the Legion plan their routes over.
- **Bisect:** find which change broke something by testing an older version halfway back, then halfway again.
- **Lane, part, track:** how the alpha wave split work. A lanes were gameplay (A1 foundation to A7 features),
  B lanes were models, maps and sound (B1 Juggernaut model to B6 test bench). LOOK, LOOK2, LOOK3, MAPS2, CLIP,
  R1-R3, V014, V015 were later single jobs. Each has a report in `~/Forge/sessions/juggernaut-alpha/results/`.
- **Relay NN, session names (Ami, Noa, Tetsu...):** Relay runs Claude sessions as numbered tasks; each picks a
  name for the crew board. "Relay 62" is task 62.
- **m39, export v7:** the Juggernaut model's revision number in Blender, and the export number the game uses.
- **Headless:** run with no window. **Off screen:** a real window drawn on the real graphics card, but on a private
  virtual screen nobody sees.
- **USGS, NRW:** the US Geological Survey and the German state of North Rhine-Westphalia, whose free elevation data
  the real-place maps are built from.
- **mesa, libLLVM:** the Linux graphics driver and a library it needs; for a while their versions did not match and
  bot runs needed a workaround (crew note 770). The mesa 26.2.4 update fixed it; bot runs worked on 2026-10-07.
