# Eighty Six: the save game and its file format

date: 2026-10-08 · for: both

This covers spec 5.1 "Save game" (P0), AAA plan feature 9 "safe saves" and engine-neutral rule 7.10
("saves as versioned JSON with a chain of migrations"). The code is `scripts/core/save_game.gd`
(`class_name SaveGame`) and the tests are `tests/test_save_game.gd`.

## What it is

It stores one campaign. Nothing calls it yet: there are no menus (Continue, New campaign), no campaign
runner and no checkpoints. Those come next and are built on this API.

- **Files** in `user://saves/` (on Linux: `~/.local/share/godot/app_userdata/Eighty Six/saves/`):
  `campaign.json` (the main save, between missions) and `autosave_0.json`, `autosave_1.json`,
  `autosave_2.json` (checkpoints, rotating: each one replaces the oldest).
- **Atomic writes.** A save goes to `<file>.tmp`, is read back, compared with what was meant to be
  written and loaded as a save (it must parse and pass `check()`), and only then renamed over the old
  file. If the game dies half way, the old file is still
  there and still loads. A stale `.tmp` is ignored on load and written over by the next save.
- **Refuses what would not come back the same.** `check()` turns away a measure that is NaN or
  infinite (JSON has no such numbers), a count that is not whole (3.7 rounds is refused, not saved as
  3), and a key that is not text (JSON would turn key 7 into "7"). The save returns `ERR_INVALID_DATA`
  and the old file stays as it was.
- **Never overwrites what it cannot read.** If the file about to be replaced is damaged, or comes from a
  newer game, it is first renamed to `<name>.kept-YYYY-MM-DD-HHMMSS.json` and left in the folder.
- **Newest good file wins.** `load_game()` reads all four files and picks the readable one with the
  highest `meta.seq`. Every save, main or autosave, takes the highest seq on disk plus one. So a damaged
  main save falls back to the newest good autosave, and a checkpoint made after the last main save is
  where Continue resumes.
- **Migrations.** Any older version climbs `_step(v, data)` one version at a time up to `VERSION`
  (2 today). The file on disk keeps its old version until the game saves again.

## The API

```gdscript
var store := SaveGame.new()                 # store.folder defaults to "user://saves"
var data := SaveGame.new_campaign_from_game()   # first mission in missions.json, whole squad alive,
                                                # emblem and finish from Settings
store.start_campaign(data)   # New campaign: the old campaign's files go to <name>.previous-<time>.json,
                             # then data becomes the main save
store.save_game(data)        # -> OK, or the error (ERR_INVALID_DATA names the problem in a warning)
store.autosave(data)         # into the oldest of the three slots
store.has_save()             # a readable save exists (for the Continue button)
var back := store.load_game()   # newest readable save, migrated; {} when none
store.last_load              # {"from": path, "damaged": [paths], "newer": [paths], "migrated_from": 0 or n}
store.load_file(path)        # one file, migrated, or {}
SaveGame.new_campaign(first_mission, squad_ids, names, emblem, finish, mech)   # pure
SaveGame.migrate(dict)       # pure: any old version up to VERSION, or {} if the chain has a hole
SaveGame.normalise(dict)     # pure: JSON floats back to ints where the format says counts
SaveGame.check(dict)         # pure: "" or what is wrong ("campaign.done.m0.grade is not one of S, A, B, C, D")
SaveGame.strip_meta(dict)    # pure: the save without its meta block
SaveGame.measure(x)          # pure: x on the 0.001 grid the file holds
```

The pure functions use only dictionaries, arrays and numbers, so a port to another engine re-types them
as they are. File, folder and clock calls sit only in the instance methods.

Tests point `store.folder` at `user://test_saves` (the same idea as sortie_log's `records_file`). The
player's own folder is never touched by a test run.

## The format, version 2

UTF-8 JSON, one object, keys sorted, tab-indented. Units are SI: seconds, metres, fractions 0 to 1.
Ids are the registry ids from `data/*.json`.

```json
{
	"version": 2,
	"meta": {"seq": 7, "saved_unix": 1791460000, "game": "0.1.1-alpha"},
	"campaign": {
		"reached": "frontier_sweep",
		"done": {
			"ashen_first_contact": {
				"grade": "A",
				"wins": 3,
				"bests": {"score": 81.0, "time_s": 312.5, "accuracy": 0.378, "longest_kill_m": 812.0}
			}
		}
	},
	"squad": {
		"alive": ["werewolf", "laughing_fox", "gunslinger", "snow_witch"],
		"fallen": [{"id": "kujo", "mission": "m1"}]
	},
	"names": ["Kujo Nico", "Kaie Taniya"],
	"loadout": {"mech": "juggernaut_m2", "kit": [], "ammo": {}},
	"emblem": "undertaker",
	"finish": "undertaker_field"
}
```

| Field | Type | Meaning |
|---|---|---|
| `version` | whole number | format version; 2 today. Missing or below 1: damaged. Above `VERSION`: from a newer game, not loaded, kept aside before any overwrite |
| `meta.seq` | whole number | save counter shared by the main save and the autosaves; the highest readable one is loaded |
| `meta.saved_unix` | whole number | seconds since 1970 (UTC) at the save; breaks ties |
| `meta.game` | text | `application/config/version` of the game that wrote it |
| `campaign.reached` | mission id | the mission the campaign stands at (Continue starts here) |
| `campaign.done` | object: mission id to record | missions finished |
| `….grade` | "S", "A", "B", "C" or "D" | the best grade, as `sortie_log.gd` grades it |
| `….wins` | whole number, 0 or more | times won |
| `….bests` | object: name to number | personal bests, the `sortie_log` names: `score` (points), `time_s`, `accuracy` (0 to 1), `longest_kill_m`. Open-ended: a new best is a new key |
| `squad.alive` | list of squad ids | who of the squad still flies |
| `squad.fallen` | list of `{id, mission}` | who fell, and in which mission (for the names screen and its carving beat) |
| `names` | list of text | the names Shin carries, in order. Starts empty; the 559 he carries into M0 are still to be written (spec 4.4) |
| `loadout.mech` | mechs.json id | `juggernaut_m2` or `juggernaut_m2_blades` |
| `loadout.kit` | list of ids | extra kit (the long-barrel gun kit, for example) |
| `loadout.ammo` | object: round id to whole number | the ammunition mix, in rounds |
| `emblem` | emblems.json id | the personal mark |
| `finish` | finishes.json id | paint and wear |

**Measures are kept to 3 decimal places** (1 ms, 1 mm, 0.1 %). Godot 4.7.2's JSON parser reads some
full-precision doubles back one bit off, and how many depends on the range. The first figure here,
980 of 10,000, did not record its range; the fix round re-measured it (see below): 1,326 of 10,000 in 0
to 1, 201 of 10,000 in 0 to 5,000, and 0 of 10,000 in 0 to a million. A value on the 0.001 grid comes back exact (200,000 of 200,000 measured),
and any engine whose parser rounds correctly reads it back exactly too. `normalise()` puts every best on
that grid before it is written.

Unknown extra top-level keys are carried through as they are, so a field added later does not break an
older reader of the same version.

### Version 1 (on paper only)

This is the layout spec 5.1 first described. No shipped build ever wrote it. It is the first link of the
chain, so the migration path is tested from day one:

```json
{"version": 1, "mission": "frontier_sweep", "alive": ["werewolf"], "names": ["Kujo Nico"],
 "loadout": "juggernaut_m2_blades", "emblem": "undertaker",
 "records": {"ashen_first_contact": {"score": 81, "time_s": 312.5, "accuracy": 0.378,
                                     "longest_kill_m": 812, "wins": 3}}}
```

Step 1 to 2: `mission` becomes `campaign.reached`. Each record becomes a `campaign.done` entry, with its
grade worked out from the recorded score by `sortie_log.grade_of`; a record with no score gets a D.
That D is a chosen default, not a real grade: `grade` is required in version 2 and there is no score
to grade from. Version 1 never shipped, so no player can meet it; `test_a_version_one_record_without_a_score_gets_a_d`
pins it.
`alive` becomes `squad.alive` and `fallen` starts empty. `loadout` becomes `loadout.mech`. `finish` is
added as `undertaker_field`.

## How to extend it

**A new field, or a changed shape.**
1. Raise `VERSION`.
2. Change `new_campaign`, `normalise` and `check`.
3. Add a `MIGRATIONS[old]` line and a `match` branch in `_step` that turns the old layout into the new one.
4. Add a test that writes a file in the old layout and loads it, like
   `test_a_version_one_file_migrates`. `test_every_version_has_a_migration_step` fails if a step's line
   is missing.

Never edit an old step: each step knows only its own two layouts.

**A new best:** no change needed. `bests` takes any name.

**A new autosave count:** change `AUTOSAVES`.

## Verified

All runs were headless, with `tools/run_tests.sh test_save_game`.

- **All 15 tests in `test_save_game.gd` pass.** The final run printed "15 passed, 1 failed"; the one
  failure was another helper's new `test_textures.gd`, which does not compile, and is not part of this
  work. The 15 cover:
  - 100 random round trips (seed 86) come back equal, with exact types, apart from `meta`. They mix
    unicode, quotes, newlines and backslashes in names, up to 40 names, up to 6 missions, and the main
    save and autosaves alternately.
  - A damaged main save (cut off half way) falls back to the newest good autosave. With that autosave
    damaged too (valid JSON, wrong shape), it falls back to the next one.
  - A version 1 file migrates.
  - A write killed after 40 bytes leaves the old save byte-for-byte untouched, and the old save still
    loads. The next save goes through.
  - Rotation keeps exactly the three newest autosaves.
  - Damaged files and files from a newer game are moved aside, not overwritten.
  - Measures are held to 3 decimal places.
  - `check()` names what is wrong.
  - A new campaign built from the game data is valid.
- **The round-trip test went red first.** In its first run, 6 of 100 round trips differed by the last bit
  of a float. That is how the Godot parser issue above was found.
- **Godot parser figures.** I measured them with throwaway `godot --headless --script` runs:
  - 980 of 10,000 random doubles came back one bit off, with `full_precision` on;
  - 0 of 200,000 values on the 3-decimal grid came back off;
  - 7 of 200,000 values on a 6-decimal grid came back off.
- **The tests can catch the faults they target.** I broke the code on purpose in two ways and three tests
  went red:
  - writing straight to the real file instead of a temp file, which fails the killed-write test;
  - not setting aside unreadable files, which fails both set-aside tests.

  The code was restored afterwards and all 15 tests pass again.
- **A test run never touches the player's saves.** After a run there is no `saves/` folder in
  `~/.local/share/godot/app_userdata/Eighty Six/`, and the test scratch folder is removed.

## Reasoned, not verified

- **The rename on Windows and macOS.** On Linux, a rename over an existing file is atomic. On Windows I
  have not checked that Godot's `DirAccess.rename_absolute` replaces an existing file in one step; the
  game has never been run on a real Windows PC.
- **Power loss.** `FileAccess.flush()` hands the data to the operating system but does not force it onto
  the disk. After a power cut (not a killed process), the newest file could come back empty. In that case
  the fallback to the other three files covers it.
- **A file can be damaged and still look valid.** There is no checksum, so a flipped bit inside a name
  still loads. Damage is detected only when the file does not parse or has the wrong shape. A checksum
  across engines would need byte-identical JSON writers, so I left it out.
- **Starting a new campaign over an old one.** (Superseded by the fix round below: use
  `start_campaign`.) `new_campaign` + `save_game` simply becomes the newest save. The old campaign's
  autosaves stay on disk with lower seq numbers until they rotate out, and if the new main save were then
  damaged, `load_game()` would fall back to them as if they were the current campaign.

## Fix round (2026-10-08)

An independent critic probed the store and found one major and five minor problems. All six are dealt
with below. Each behaviour fix got a test first, and each new test was seen red before the fix (4 red:
three failed assertions, one script error for the missing `start_campaign`).

1. **Major: a NaN or infinite measure saved as a file that could not be read back.** `check()` only
   asked "is it a float". Godot writes NaN as `null`, so `save_game()` returned OK while replacing a
   good main save with one that loads as damaged. Fixed in two layers:
   - `check()` now refuses a best that is not finite ("campaign.done.m0.bests.accuracy is not a finite
     number"). This also covers a finite value so big that the 0.001 grid overflows it to infinity
     (1e306).
   - `_write` now loads the temp file as a save (`_read(tmp)`) as well as comparing its bytes. A temp
     file that does not load never replaces the old save (`ERR_FILE_CORRUPT`).
   Test: `test_a_measure_that_is_not_finite_is_refused_and_the_old_save_kept` (NaN, INF, -INF and 1e306
   through `save_game` and `autosave`; the old `campaign.json` stays byte-identical and still loads).
2. **Fractional counts were rounded down.** `normalise()` turned any number into an int. Now only a whole,
   finite number becomes a count (`_is_whole`), so 3.7 rounds and 2.9 wins reach `check()`, which
   refuses them; 2.0 and 40.0 still load as ints. Test:
   `test_a_count_that_is_not_whole_is_refused_not_rounded_down`.
3. **Keys that are not text.** `check()` now refuses a key in `campaign.done`, in a `bests` object or in
   `loadout.ammo` that is not text. Test: `test_keys_that_are_not_text_are_refused`.
4. **The fallback could cross campaigns.** New `start_campaign(data)`: it checks `data` first (a bad
   campaign moves nothing), then moves the old campaign's four files aside to
   `<name>.previous-YYYY-MM-DD-HHMMSS.json` (never deleted), then writes `data` as the main save. Test:
   `test_a_new_campaign_never_falls_back_to_the_old_one` (old main save plus three autosaves; after
   `start_campaign` the main save is emptied, and `load_game()` returns nothing rather than the old
   campaign; all four old files are in the folder as `.previous-` files).
   I chose this over a campaign id stamped in the file. An id alone cannot help when the new campaign's
   only file is the damaged one, because nothing readable then says which campaign is current.
5. **A version 1 record with no score gets a D.** This is now documented as the chosen default (see
   "Version 1"), and a test pins it. Version 1 never shipped, so there was no code change.
6. **The parser figure did not name its range.** Re-measured with a throwaway
   `godot --headless --script` run (seed 86, 10,000 values per range, writer with `full_precision`):

   | Range | Full-precision values off by a bit | Values on the 0.001 grid off |
   |---|---|---|
   | 0 to 1 | 1,326 of 10,000 | 0 of 10,000 |
   | 0 to 5,000 | 201 of 10,000 | 0 of 10,000 |
   | 0 to 1,000,000 | 0 of 10,000 | 0 of 10,000 |

   The critic's own run in 0 to 5,000 (seed 1) gave 191 of 10,000. The comment above `MEASURE_PLACES`
   now gives these figures with their ranges. The decision itself (3 decimal places) stands.

**Verified in the fix round** (`tools/run_tests.sh test_save_game.gd`, headless):
- All 20 tests in `test_save_game.gd` pass. The final run printed "20 passed, 3 failed". The three
  failures are files that do not compile at the moment: `test_legs_realmesh.gd` (Riku's), and
  `test_textures.gd` and `test_world_look.gd` (other helpers' work in progress). None is part of this
  item. The new-campaign test also checks that `start_campaign` with a campaign that would not save
  returns an error and moves nothing aside. That check passed on its first run, because it was written
  after the code.
- Mutation check on the NaN fix. Each guard was switched off in turn and the code restored afterwards
  (byte-compared with a backup):
  - With the finite check off and only the read-back left, NaN was still refused, but INF, -INF and 1e306
    were saved. Godot reads its own `1e99999` back as infinity, so those files load. The finite check is
    therefore the guard that matters, and the read-back is a second net for whatever `check()` misses.
  - With both off, NaN was saved as well.
  - With only the read-back off, the test passes.
- No `saves/` or `test_saves/` folder is left in `~/.local/share/godot/app_userdata/Eighty Six/` after
  the run.

**Reasoned, not verified.** A file written by an older build that holds a fractional count, a non-finite
measure or a number key is now treated as damaged on load, where before it was rounded or carried
through. No build has written such a file (nothing calls SaveGame yet), so no real save is affected.

**For Emerson.** New campaign should call `start_campaign`, not `save_game`. The old campaign is never
deleted: it stays in the saves folder as `.previous-` files, and nothing in the game reads them back.
Whether the menu should offer to restore one is a later menu decision.
